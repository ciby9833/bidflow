# 招标延期与重新开放

## 已实现业务规则

- `published` / `open` 可延长；`closed` 可重新开放当前轮次。
- 新时间必须晚于当前时间、原截止时间和开始时间。尚未到开始时间的 `published` 保留开始时间及状态。
- 不改变轮次、邀请名单、报价、币种、排名规则、改价次数、最小降幅或冷却时间。
- `draft` / `cancelled` / `awarded` 拒绝操作。没有历史轮次重开入口。
- 只允许本机构具有 `tender:deadline_adjust` 权限的用户写入。默认采购经理及超级管理员具有该权限，采购专员和供应商没有。
- 内部原因与供应商公告分别填写；供应商及大厅响应不包含内部原因、操作人、邮件地址等管理信息。
- 不建立 Shortlist、BAFO 或审批流程；线下采购进度仍由操作人判断。

## 入口与接口

采购端招标详情 → 截止时间变更 → 延长截止时间 / 重新开放报价。

- `GET /api/tenders/:id/deadline-changes/preview`：当前轮次、状态、行版本、更新时间、机构时区、报价人数、邮件收件人数。
- `POST /api/tenders/:id/deadline-changes`：`newDeadline`（带时区 ISO）、`reason`、`announcement`、`expectedRound`、`expectedStatus`、`expectedUpdatedAt`、`expectedVersion`、`idempotencyKey`。
- `GET /api/tenders/:id/deadline-changes`：最近 100 条记录，先校验招标可见性。
- `POST /api/tenders/:id/deadline-changes/:changeId/retry`：重新排队失败邮件。
- 供应商桌面/手机详情、报价页显示公告；公开大厅详情沿用原大厅访问控制后附带公告。

## 数据与并发

新增迁移 `1713730000034-TenderDeadlineChanges.ts`，只新建 `tender_deadline_changes` 和 `tender_deadline_mail`。
两表由迁移及参数化 SQL 管理，不依赖 TypeORM schema synchronization。

延期事务锁定招标行，校验机构、轮次、状态、`xmin` 行版本及更新时间；修改时间和状态、写审计、变更记录和邮件任务同时提交。
同一幂等键及同一请求重试返回原结果；同一幂等键对应不同请求拒绝。新的请求需重新预览取得版本。

关标、开标及撤回使用条件更新，创建下一轮锁行并重新校验。报价最终写入事务持有共享招标行锁并重新检查状态、轮次、数据库时间。
到期请求使用条件更新，避免旧请求覆盖已经延长的截止时间。

## 通知范围

- 定向标：本轮受邀供应商中，当前具有本机构有效档案、审核通过且活跃的供应商及账号。
- 公开参与标：上述条件下已提交报价的供应商；不向整个供应商目录群发。现有标包报价未分轮次，其历史响应也纳入已知联系人；线路报价限定本轮。
- 所有有权限查看招标的供应商都可看到公告；启用公开大厅的标在原大厅也展示公告。
- 公告不受旧 `notifySuppliers` 邀请开关影响。预览人数基于当时数据，事务会重新计算收件人。
- 本版没有订阅、邮件已读回执或自动修改标书/PDF的能力。

后台每 30 秒处理最多 20 个邮件任务，失败间隔 5 分钟重试，3 次失败后支持手动重试。
多实例通过行锁及 5 分钟租约领取任务。发送成功但进程未确认就崩溃时可能重复发送（至少一次投递），不会重复修改招标。
SMTP 未配置时明确记录失败，不把本地 stream transport 当成真实发送成功。
管理员可刷新变更记录查看发送/失败数。已有记录永久保留；变更已生效后不得通过回滚数据库抹去期间产生的报价。

数据库测试只建立并清理唯一名称的隔离 schema；使用测试/开发连接运行，需要 CREATE SCHEMA 权限。不在生产库运行测试。

## 上线顺序

1. 核对要发布的代码及待执行迁移；当前工作区还包含供应商、汇率等其他修改，不能把整个工作区视为本功能独立发布包。
2. 按正常发布流程备份数据库，构建后先执行迁移，再重载后端并发布前端。迁移前启动新版会出现新表不存在错误。
3. 使用 `npm run migration:run` 会执行所有待执行迁移，必须先核对清单，不能只依据本说明直接在生产执行。
4. 采购经理刷新登录能力后应出现入口；验证另一机构和供应商账号无法调用修改接口。
5. 用测试标验证一次延期、一次重开及通知，确认 SMTP 正常。正式标应填写实际公告，并人工核对后续谈判时间及标书附件。

本次开发没有执行生产迁移、修改生产招标或发送生产邮件。
