# 供应商多机构规则与回归检查（注册、认证、准入与登录）

## 业务边界

- 一个供应商公司主档可关联多个采购机构；公司注册国家不等于采购机构所在国。
- 公司资料、商务编号、认证状态及全局挂起状态共享；机构准入关系分别启用／撤销。
- 新建公司默认采用目标机构国家，用户可以明确选择实际注册国。编辑、登录及切换机构不得重新套用默认值。
- 商务编号是稳定标识。国家更正不自动重编编号；历史数据须核实真实注册国后逐条修正，不按关联机构批量改国别。
- 邮箱或 Google 注册只建立账号。认证时创建公司并加入首个机构；邀请加入公司不再创建公司，也不等同于采购机构准入。
- 其他机构通过精确编号引入已有供应商，不复制公司。只有目标机构有管理权限的用户可以执行准入操作。
- 一个账号只使用一个当前业务机构。单机构直接进入；多机构沿用仍有效的上次选择，否则先选机构。桌面与移动端均可切换。
- 切换会重新签发令牌、使旧令牌失效、清理移动端返回路径并返回大厅。未保存编辑先提示；不会改变公司注册国。
- 撤销本机构准入不删除公司或其他机构关系；当前实现会要求该公司关联账号重新登录。全局挂起则影响所有机构。

## 材料与权限

- CN／ID 沿用现有材料模板；VN 及其他国家采用通用“公司注册证明／支持材料”收集项，不将其宣称为当地法定材料清单。
- 国家专属合规要求需业务另行确认后扩充模板。已有非模板材料在回填、切换国家、再次提交时保留。
- 账号导入必须指定可管理的目标机构（普通机构固定当前机构，总部明确选择），仅能向该机构已准入供应商添加账号。
- 公司资料属于共享主档，因此当前准入机构的管理操作可能影响其他机构看到的公司信息；界面明确提示此边界。

## 验证

后端目录执行 `npm run build && node --test scripts/test-supplier-multibranch.js`。
测试使用内存替身，不连接数据库，不创建真实账号或供应商。
前端目录执行 `npm run build`。

人工验收场景：

1. 越南机构创建供应商，默认 VN；明确选择 ID 则保持 ID，所属机构仍是越南。
2. 总部手工／批量创建及账号导入必须明确目标机构；空国家跟随机构，非法国家返回错误。
3. 新供应商选择越南机构首次认证，提交成功后可看到审核进度；不会保存成功却提示不存在。
4. 已有 VN 公司通过桌面或移动端补件，国家仍为 VN，旧材料不消失。
5. 使用新机构的空供应商列表引入已有商务编号，公司主档不重复创建。
6. 同一供应商准入 ID／VN 后，首次多机构登录可选择，后续登录记住上次；Google 与密码登录一致。
7. 从 ID 报价详情切换 VN，先确认未保存内容丢失，再返回 VN 大厅，不沿用旧详情与返回栈。
8. 无准入关系时不能导入该供应商账号；撤销本机构准入后仍保留其他机构准入。

本次代码修复不自动修改历史供应商国家、编号，也不运行数据迁移。
